# ADR-003: Use a Relational Database

## Problem

The system needs to store information about employees, departments, requests, and request statuses.

These entities have clear relationships between them. For example, an employee can submit many requests, and a department can handle many requests.

Because of these relationships, we need to choose a database model that keeps the data structured and consistent.

## Options

### Option 1: Relational database

Use a relational database to store the system data.

Advantages:
- Works well with the relationships between employees, departments, and requests.
- Makes it easier to use joins when retrieving related data.
- Provides a clear and structured schema.
- Helps keep the data consistent.

Disadvantages:
- The schema is less flexible if the structure of the data changes a lot.

### Option 2: Document database

Use a document database where data can be stored in more flexible documents.

Advantages:
- More flexible structure.
- Easier to change the shape of the stored data.

Disadvantages:
- The flexibility is not really needed for the current system.
- Managing the relationships between the main entities can become more complicated.

## Decision

We decided to use a relational database.

The system has clear relationships between employees, departments, staff, and requests, so a relational model fits the current needs better.

The system also needs to retrieve related information often, such as requests submitted by an employee or requests handled by a department.

## Consequences

### Positive
- Relationships between the main entities are easier to manage.
- Queries using related data are easier to create.
- The data structure stays consistent.
- The database fits the current access patterns of the system.

### Negative
- Changes to the data structure may require schema changes.
- It is less flexible than a document database.

### Future Consideration

If the type of data stored by the system changes a lot in the future, this decision can be reviewed.
